## 1. 학부 캡스톤: Attention-LSTM으로 가격 수준 예측

- **시도:** 거시경제·기후 데이터를 붙여 14일 뒤까지의 가격을 예측했다. VAR, LSTM, Entmax Attention을 붙인 LSTM을 비교했다.
- **결과:** 가격 RMSE는 VAR 10.23, LSTM 6.70이었다. 숫자는 좋아 보였지만 비교할 기준선이 없었다.
- **나중에 찾은 문제:** 테스트 입력을 스케일링하지 않았고, 테스트 손실을 보며 학습률과 epoch를 조정했다. 방향 손실을 `sign()`으로 계산해 기울기가 0이었고, 결측을 병합 전에 앞 값으로 채워 미래 정보가 섞였다. 80/20 한 번 분할이었다.
- **결정:** 같은 문제를 기준선과 시간 순서 평가부터 다시 설계한다(노트북 01의 7절).

## 8. 첫 비교에서 모든 지평이 Naive였다

- **시도:** 2015년부터 학습하고 한 번 나눈 검증 구간으로 비교했다.
- **결과:** 세 지평 모두 현재가 유지(Naive)가 가장 좋았다. 60일 LightGBM은 RMSE가 8% 낮았지만 균형정확도가 0.49였다.
- **결정:** Naive와 50% 방향은 기준선일 뿐 예측이 아니다. 그래서 학습 설계를 바꿨다. 자료를 2005년부터 모으고 2006년부터 학습했다. 2012–2021년 연도별 walk-forward 10회로 고르고, 2022–2025년은 보류 구간으로 남겼다. 원산지 통화(헤알·페소), 해상 운임, 이상기후 파생변수, ENSO, 해거리 주기를 추가했다. 방향 확률 + 판단 보류(C1)와 변동성 예측(C2)을 함께 보기로 했다.
- **근거:** `f6851d9`, 계획 변경 기록

## 10. 무엇이 예측되고 무엇이 안 되는가

- **수익률(노트북 03):** 모든 모델이 Naive보다 나빴다. 5일 LightGBM +0.9%가 가장 가까웠다. 학부 모델에서 Attention·정적 피처 분기·복합 손실을 뺀 단순 LSTM은 20일에서 +16.7%였다.

## 13. 서비스 다시 만들기

- **DB:** 예측 행은 덮어쓰지 않는다. 같은 기준일에 backfill이 있으면 live는 저장되지 않는다. 활성 모델은 부분 유일 인덱스로 하나만 허용한다. 일별 뉴스 점수 테이블은 `news_articles`에서 언제든 다시 계산할 수 있어 만들지 않았다.
- **API 이미지:** `db.py`가 pandas 없이 동작하게 해 API 이미지를 274MB로 줄였다. 파이프라인 이미지는 torch를 빼 2.78GB에서 1.05GB가 됐다.
- **뉴스 소스:** Yahoo KC=F 뉴스는 2026-10-03 확인 시 0건이라 뺐다. Google News RSS 제목 형식과 해시를 보관 분석과 맞춰 같은 기사를 다시 분류하지 않는다. 실제 실행 한 번에 10건을 분류했고 비용은 0.000144 USD였다.
- **검증:** 임시 PostgreSQL 17.11로 pytest 37개, 실제 backfill·daily 실행, 컨테이너 안 migrate·backfill, 브라우저 확인(데스크톱·375px, 밝은·어두운 화면)을 했다. VM과 GitHub Actions 실제 실행은 운영 전환 때 한다.
- **의존성 확인(2026-10-03):** GitHub Actions는 기존 SHA(checkout v5.1.0, setup-python v6.3.0, setup-node v5.0.0)가 공식 태그와 일치하고 모두 node24 런타임이라 유지했다. 최신 major(v7)로 올릴 이유가 없었다. 프론트는 기존 고정 버전(vue 3.5.43, vite 8.3.0, @vitejs/plugin-vue 6.0.8)을 유지했다. 패치(vite 8.3.2)가 있지만 `npm audit`이 0건이다. 기반 이미지는 digest로 고정했다(python 3.12.15, node 22.23.3, nginx 1.30.5, postgres 17.11, caddy 2.11.4).

## 15. 외부 리뷰 반영 (1): 성적 분리와 LSTM 표현

- **상황:** 다른 모델에게 `main`과 비교하는 리뷰를 받았다. 지적 세 가지를 코드로 확인했고 모두 맞았다.
- **실시간·소급 성적이 섞였다:** 대시보드 적중 기록은 실시간 건수만 따로 세고, 적중률은 소급 계산과 합쳐 계산했다. 소급 100건이 모두 맞고 실시간 10건이 모두 틀려도 90.9%로 보인다. 두 표로 나눠 따로 계산하게 고치고 이 사례를 테스트로 넣었다.
- **LSTM 표현이 과했다:** 노트북 03의 LSTM은 학부 모델에서 Attention·정적 피처 분기·복합 손실을 뺀 단순 LSTM인데, README와 이 기록에는 "학부 때 구조"라고 썼다. "단순 LSTM 기준 모델"로 고쳤다. 원래 캡스톤 모델을 다시 검증한 것은 아니다.
- **평가 표본 누락(다음 항목에서 수정):** walk-forward 평가 행에도 "목표일이 그해 안" 조건을 걸어, 60일 예측은 해마다 10–12월 기준일이 빠졌다. 설정을 그대로 두고 빠진 행만 넣어 다시 계산하면 보류 구간 60일 방향 표본이 690개에서 856개로 늘고, AUC는 0.655에서 0.601로, 60일 변동성은 직전 변동성 대비 −1.9%에서 +1.9%로 바뀐다. 개발 구간의 선택(피처·수축·임계값·범위 배율)도 다시 해야 해서 노트북 02–06을 다시 실행해 고친다.
