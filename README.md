# 커피 선물 가격 범위 예측

> 아라비카 커피 선물(KC=F)이 **5·20·60거래일 뒤 어느 가격 범위에 있을지** 매일 예측해 공개하는 1인 데이터 프로젝트입니다. 데이터 수집, 탐색 분석, 실험 설계와 검증, 자동화 파이프라인, 대시보드 운영까지 혼자 진행했습니다.

## 분석에서 찾은 것

| 질문 | 발견 | 결정 |
|---|---|---|
| 가격을 맞힐 수 있는가 | Ridge·LightGBM·LSTM 모두 "현재가 유지" 기준선을 넘지 못했다. 단순 LSTM은 20일 RMSE가 기준선보다 17.1% 컸다 | 가격 하나를 맞히는 대신 **범위와 위험**을 예측하도록 목표를 바꿨다 |
| 변동성은 예측되는가 | 최근 5·20·60일 변동성으로 다음 변동성을 예측하는 HAR 모델이, 직전 변동성을 그대로 쓰는 것보다 RMSE를 5일 25%, 20일 14% 줄였다. 2022–2025에도 27%, 20%. 60일은 차이가 뚜렷하지 않았다. 2022–2025에서는 평균 수준을 더 잘 맞춘 효과였고, 급등락 시점을 맞힌 것은 아니다 | 예측 범위의 폭을 변동성 예측으로 정한다 |
| 뉴스가 가격을 앞서는가 | 뉴스 점수는 기사 **당일** 수익률과 상관 0.21, 이후 수익률과는 뚜렷한 관계가 없었다 | 뉴스는 가격을 따라간다고 보고 보조 입력 1개로만 쓴다 |
| 기후는 어떻게 넣는가 | 2021년 브라질 서리 때 평균기온은 평년보다 0.7℃ 낮았을 뿐이지만 최저기온은 5℃ 안팎 낮았다 | 기온·강수를 값 그대로가 아니라 직전 10년 같은 시기 대비 **편차**로 넣는다 |
| 원자료를 믿을 수 있는가 | 1,910 안팎이던 페소 환율이 하루만 3.67로 잘못 기록돼 있었다. 이 값 하나가 60일 예측 분포의 폭을 정하는 σ를 61,083까지 키웠다. 흔한 IQR 1.5배 이상치 규칙은 페소 일간 변화의 7.9%를 이상치로 잡았다 | 실제 자료로 규칙을 비교해 정했다(IQR 20배). 바뀐 값은 18개뿐이다 |
| 앙상블이 돕는가 | 9월 실험에서 60일 모델 둘의 평균은 단일 모델보다 RMSE가 검증에서 5.76% 낮았지만 테스트에서는 2.63% 높았다 | 이득이 재현되지 않아 기각했다 |

## 검증 방법과 모델 성적

**예측 대상.** 기준일 종가 대비 h거래일 뒤 종가의 로그수익률 ln(P<sub>t+h</sub> / P<sub>t</sub>) 분포입니다. h는 5·20·60이고, 화면에서는 이 예측 기간을 '지평'이라고 부릅니다.

| 구간 | 기간 | 쓰임 |
|---|---|---|
| 개발 | 2012–2021 | 해마다 그 전까지로 학습해 그해를 예측(walk-forward 10회). 후보와 판단 규칙을 여기서 정한다 |
| 홀드아웃 (화면의 '보류') | 2022–2025 | 개발 구간에서 정한 규칙을 그대로 적용해 확인한다. 앞선 실험에서 이미 본 구간이라 참고 성적으로만 쓴다 |
| 실시간 | 2026-10– | 동결한 모델의 매일 예측을 대시보드에서 채점한다. 처음 보는 자료에 대한 성적은 이것뿐이다 |

- **기준선과 비교합니다.** 수익률은 현재가 유지, 변동성은 직전 변동성, 범위는 현재가에 HAR 변동성 폭을 더한 것이 기준선입니다. 모든 성적은 같은 날짜·같은 예측 기간의 기준선과 비교합니다.
- **미래 정보를 막습니다.** 목표일이 학습 구간을 넘는 행은 학습에서 빼고(embargo), 모델 설정은 평가 연도 이전 성적으로만 고릅니다(중첩 검증).
- **불확실성을 함께 냅니다.** h일 수익률은 날짜가 겹쳐 서로 독립이 아니므로 블록 bootstrap 1,000회로 95% 구간을 계산합니다.
- **판단 규칙을 먼저 적습니다.** 후보와 채택 기준을 계산 전에 노트북 첫 셀에 적고 해시(SHA-256)로 고정했습니다. 분포 모델 v2는 v1의 결과를 본 뒤 고친 것이라 개발 구간도 두 번째로 본 것입니다.

**서비스 모델 `2026-10-06`.** 예측 기간마다 가운데 값과 폭을 함께 예측하는 분포 모델 하나를 씁니다(y = μ(x) + σ(x)·Z). 범위·상승 확률·매수 신호·위험 수준이 모두 같은 분포에서 나와 서로 어긋나지 않습니다. 성적은 CRPS로 잽니다. CRPS는 예측 분포가 실제 값에서 얼마나 떨어졌는지를 나타내고 낮을수록 좋습니다.

| 예측 기간 | 80% 범위 적중률<br/>개발 / 홀드아웃 | 상승 확률 AUC<br/>개발 / 홀드아웃 | 기준선 대비 CRPS<br/>개발 / 홀드아웃 |
|---|---|---|---|
| 5일 | 82.7% / 78.2% | 0.53 / 0.52 | +0.2% / −0.3% |
| 20일 | 82.4% / 79.0% | 0.56 / 0.58 | +1.4% / −1.1% |
| 60일 | 82.1% / 74.3% | 0.64 / 0.63 | +2.1% / −2.8% |

CRPS 열은 +면 기준선보다 나쁘고 −면 좋다는 뜻입니다. 분포 모델이 기준선보다 낫다는 것은 확인되지 않았습니다. 개발 구간에서는 세 기간 모두 조금 나빴고(20일만 우연을 넘는 차이), 홀드아웃에서는 조금 좋았습니다. 기준선이 이미 HAR 변동성 폭을 쓰기 때문에 변동성 예측의 이득(5일 −25%)은 기준선에도 들어 있습니다. 분포 모델을 쓰는 이유는 범위·확률·신호를 한 모델에서 어긋남 없이 내기 위해서입니다.

매수 신호는 20일에서만 냅니다. 개발 구간 시뮬레이션에서 신호대로 사면 정기 구매보다 평균 0.16% 쌌을 뿐이고, 신호 기준을 고른 자료와 채점한 자료가 같아 그 우위도 검증된 것이 아닙니다. 그래서 화면은 신호보다 범위를 먼저 보여 줍니다.

```mermaid
  J["LLM 뉴스 분류<br/>(Vercel AI Gateway)"]
  subgraph vm["Azure VM · Docker Compose"]
    DB[("PostgreSQL 17")]
    API["FastAPI<br/>읽기 전용 계정"]
    WEB["Vue 3 + nginx"]
    C["Caddy (HTTPS)"]
  end
  src --> NB --> ART --> P
  src --> P
  P <--> J
  P -- "SSH 터널" --> DB
  U["사용자"] --> C --> WEB --> API --> DB
```

**1. 모든 값에 "언제 알 수 있었나"를 붙였습니다.** 소스마다 실제로 쓸 수 있게 된 시점을 정하고 기준일에 이미 알려진 값만 붙입니다.

| 자료 | 언제부터 쓰는가 |
|---|---|
| KC=F 종가 (Yahoo) | 당일 23:00 UTC 마감 이후 |
| 페소 환율 COP=X (Yahoo) | 관측 다음 날 |
| 헤알 환율·금리·유가·운임 (FRED·ALFRED) | 최초 공개일 다음 날 (공개 기록이 없는 구간은 공개 지연을 가정) |
| ENSO (NOAA) | 3개월 계절이 끝난 다음 달 11일 |
| 산지 강수·기온 (NASA POWER) | 관측일 + 4일 |
| 뉴스 점수 (Google News → LLM 분류) | 분류가 끝난 뒤 첫 거래일 마감 |

"기준일 이후 원자료를 모두 바꿔도 기준일까지의 피처는 같다"는 성질을 테스트로 고정했습니다.

**2. 예측 기록은 결과를 본 뒤에 바뀌지 않습니다.** 기준일의 예측은 다음 종가가 나오기 전에 예약 배치가 확정하고 그 뒤에는 고치지 않습니다. 실시간 예측과 소급 계산은 따로 저장해 따로 채점합니다.

**3. 실패를 경고와 중단으로 나눕니다.** 종료 코드를 성공 0 / 경고 3 / 실패 1로 나눠, 뉴스 같은 보조 소스가 실패해도 예측은 저장됩니다. LLM 뉴스 분류는 하루 2건, 누적 1 USD 상한 안에서 돕니다.

**4. 연구와 서비스가 같은 코드를 씁니다.** 노트북과 일일 배치가 같은 `coffee` 패키지로 피처와 예측을 만들고, 노트북의 예측과 DB에 저장된 값이 같은지 확인했습니다. 모델은 버전으로 동결하고 파일 해시를 검사합니다.

## 실행 방법

`.env.example`을 `.env`로 복사해 값을 채웁니다(`FRED_API_KEY`, `AI_GATEWAY_API_KEY`, `DATABASE_URL`, `POSTGRES_PASSWORD`).

```bash
# 환경 (Python 3.12)
uv venv --python 3.12 "$HOME/.virtualenvs/coffee-price-prediction"
uv pip install --python "$HOME/.virtualenvs/coffee-price-prediction/bin/python" -r requirements.txt
source "$HOME/.virtualenvs/coffee-price-prediction/bin/activate"

python -m pytest            # DB 없이 72 passed · COFFEE_TEST_DATABASE_URL을 주면 89 passed
python -m coffee.sources    # 원자료 수집 → data/sources/*.parquet

# 로컬 전체 실행 (PostgreSQL + API + 대시보드 → http://localhost:8080)
docker compose up -d --build
docker compose run --rm pipeline migrate
docker compose run --rm pipeline backfill
docker compose run --rm pipeline daily      # 기준일의 예약 시각(종가 다음 날 06:17 UTC) 전이면 건너뜀

# 프론트엔드
cd frontend && npm ci && npm test && npm run build
```

수집 데이터(`data/`)는 저장소에 넣지 않았습니다. 노트북은 번호 순서로 실행하되 07 다음에 06을 실행합니다(07이 고른 설정을 06이 동결). 배포 절차는 [architecture.md](docs/architecture.md#배포와-되돌리기)에 있습니다.
